# 鸿蒙Flutter插件精选：change_app_name —— 一键改应用名，多 Flavor 也不怕

大家好呀～艾玛又来啦！🦊

上一期我们聊了 **flutter_umeng_common** 帮大家打通了鸿蒙数据统计。今天介绍的插件专注于一个看似简单但开发中经常头疼的问题——**改应用名**！

你有没有遇到过这样的场景：

- 开发版、测试版、生产版要用不同的 App 名字区分
- 接了多个 Flavor（如 dev/staging/prod），每个 flavor 要显示不同的应用名
- 不知道什么原因 App 名字显示乱了，排查半天发现是配置问题

手动改各平台的应用名？Android 改 `strings.xml`，iOS 改 `Info.plist`，鸿蒙改 `app.json5`……改一次三四个地方，烦不烦？😤

**change_app_name** 就是来救你的——一条命令，全平台应用名一键修改！

---

## 痛点

- **各平台应用名配置位置完全不一样**：Android 的 `android:label`、iOS 的 `CFBundleDisplayName`、鸿蒙的 `app.json5` 里的 `label`
- **多 Flavor 配置噩梦**：debug/release/staging 要不同名字，每个 flavor 都要配一次，配错就出问题
- **改完后经常莫名其妙**：改了 `strings.xml` 忘了改 `AndroidManifest.xml`，改了 `Info.plist` 忘了改 `Product Bundle Name`……
- **CI/CD 场景更要命**：自动化构建时动态改应用名，写一套 shell 脚本踩坑无数

---

## 核心特性

- ✅ **一行命令改全平台应用名**：Android、iOS、macOS、OHOS 一网打尽
- ✅ **原生支持 HarmonyOS**：自动修改 `ohos/AppScope/app.json5` 中的 `label` 字段
- ✅ **Flavor 友好**：不同构建变体可以配置不同应用名
- ✅ **零配置启动**：装好插件直接跑，自动检测各平台配置文件
- ✅ **不破坏现有配置**：精准修改，不会影响其他配置项
- ✅ **CI/CD 集成简单**：命令模式，CI 流程中直接调用

---

## 快速上手

### 1. 添加依赖

```yaml
dev_dependencies:
  change_app_name: ^1.0.0
```

```bash
flutter pub get
```

### 2. 创建配置文件

在项目根目录创建 `change_app_name.yaml`：

```yaml
name: 我的正式应用
```

也可以为不同平台单独配置：

```yaml
name: 我的正式应用
android_name: 我的应用 (Android)
ios_name: My App (iOS)
ohos_name: 我的应用 (鸿蒙)
```

### 3. 执行修改

```bash
dart run change_app_name
```

搞定！所有平台的应用名都自动更新了 ✨

### 4. Flavor 配置

对于多 Flavor 项目，可以在配置中指定：

```yaml
flavors:
  dev:
    name: 开发版
    android_name: 开发版 (Android)
    ios_name: Dev App
    ohos_name: 开发版 (鸿蒙)
  staging:
    name: 测试版
    ohos_name: 测试版 (鸿蒙)
  prod:
    name: 我的正式应用
    ohos_name: 我的应用
```

然后按 flavor 运行：

```bash
dart run change_app_name --flavor dev
```

## 环境要求

- Flutter SDK >= 3.0.0
- HarmonyOS 项目结构已初始化（`ohos/AppScope/app.json5` 存在）
- Dart SDK >= 3.0.0

---

## OHOS 修改内容详解

`change_app_name` 在 OHOS 平台上会自动修改以下文件：

| 文件 | 修改字段 | 说明 |
|------|---------|------|
| `ohos/AppScope/app.json5` | `app.label` | App 级显示名称 |
| `ohos/entry/src/main/module.json5` | `module.distro.labels` | Entry 模块显示名称 |

---

> 别看改应用名只是个小操作，跨平台项目里它真的能省不少事。特别是 CI/CD 场景，一行命令自动替换，再也不用担心手动改漏了导致上线后显示名字不对！
