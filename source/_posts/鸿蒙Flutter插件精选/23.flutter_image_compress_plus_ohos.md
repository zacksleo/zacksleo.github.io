# 鸿蒙Flutter插件精选：flutter_image_compress_plus_ohos —— 图片压缩的另一种选择

大家好呀～艾玛又来啦！🦊

上一期我们聊了 **tencent_kit** 腾讯开放平台的接入。今天要介绍的插件和之前第 17 期的 `image_compress_plus_ohos` 类似，但它是另一个独立的包——**flutter_image_compress_plus_ohos**！

为什么会有两个类似的插件？因为在鸿蒙 Flutter 生态早期，不同的开发者各自对 `flutter_image_compress` 做了鸿蒙适配，于是诞生了两个包：

- `image_compress_plus_ohos`（第 17 期介绍）
- `flutter_image_compress_plus_ohos`（今天的主角）

两个包的目标一致——在鸿蒙上实现高效的图片压缩，只是实现方式和 API 风格略有不同。今天我们来详细了解 `flutter_image_compress_plus_ohos` 的特点！🖼️

---

## 痛点

- **flutter_image_compress 未原生支持鸿蒙**：这是所有图片压缩需求的根源痛点
- **选择困难**：多个鸿蒙压缩方案，不知道选哪个好
- **压缩效果需要对比**：不同实现的压缩率和质量可能有差异
- **兼容性考量**：跟现有项目的 `flutter_image_compress` 代码兼容性如何？

---

## 核心特性

- ✅ **保持与 flutter_image_compress API 高度兼容**：如果你的项目已经在用 `flutter_image_compress`，迁移成本极低
- ✅ **支持质量压缩**：按 1-100 的质量值压缩图片
- ✅ **支持尺寸压缩**：按最大宽度/高度缩放图片尺寸
- ✅ **格式转换**：JPEG、PNG、WebP 格式互转
- ✅ **自动旋转**：自动根据 EXIF 方向信息校正图片
- ✅ **保持 EXIF**：支持保留 EXIF 元数据
- ✅ **支持 Uint8List 路径双模式**：内存/文件双输入
- ✅ **原生性能**：基于鸿蒙多媒体框架实现，性能可靠

## 快速上手

### 1. 添加依赖

```yaml
dependencies:
  flutter_image_compress_plus_ohos: ^0.1.0
```

```bash
flutter pub get
```

### 2. 基本使用

```dart
import 'package:flutter_image_compress_plus_ohos/flutter_image_compress_plus_ohos.dart';

final compressor = FlutterImageCompressPlusOhos();

// 文件路径压缩（按质量）
final result = await compressor.compressAndGetFile(
  '/path/to/original.jpg',      
  '/path/to/compressed.jpg',    
  quality: 70,                  
  minWidth: 1080,               
  minHeight: 1920,              
);
```

### 3. 按目标大小压缩

```dart
final compressed = await compressor.compressAndGetFileWithTargetSize(
  '/path/to/original.jpg',
  '/path/to/compressed.jpg',
  targetSize: 500 * 1024,   // 目标 500KB
  minWidth: 720,
  minHeight: 1280,
);
```

### 4. 从内存压缩

```dart
final Uint8List originalBytes = await loadImageBytes();

final compressedBytes = await compressor.compress(
  originalBytes,
  quality: 60,
  format: CompressFormat.jpeg,
);

// 压缩后的字节数据可以直接显示或上传
// Image.memory(compressedBytes)
```

### 5. 转换为 WebP 格式

```dart
final result = await compressor.compressAndGetFile(
  '/path/to/image.png',
  '/path/to/image.webp',
  quality: 80,
  format: CompressFormat.webp,   // 输出 WebP
);
```

### 6. 对比两个方案

| 特性 | `image_compress_plus_ohos` | `flutter_image_compress_plus_ohos` |
|------|--------------------------|-----------------------------------|
| API 风格 | 偏向独立封装 | 更贴近 flutter_image_compress 原有 API |
| 目标大小压缩 | ✅ 支持 | ✅ 支持 |
| 格式转换 | JPEG/PNG/WebP | JPEG/PNG/WebP |
| 批量压缩 | ✅ 支持 | ✅ 支持 |
| 自动旋转 | ✅ | ✅ |
| 迁移成本 | 中等 | 低（与原版 API 最接近） |

## 环境要求

- Flutter SDK >= 3.0.0
- 鸿蒙系统 API 9+
- 读取文件需要 `ohos.permission.READ_MEDIA`

---

## 选哪个？

> 两个插件的核心能力几乎一致！选择建议：
>
> - 如果你已经用了 `flutter_image_compress`，想最小化改代码 → 选 **flutter_image_compress_plus_ohos**
> - 如果你是全新项目，更习惯简洁的独立 API → 选 **image_compress_plus_ohos**
> - 如果其中一个出了问题或者不再维护，可以直接切换到另一个，两者的引入方式都很简单！
>
> 鸿蒙生态正在快速成长中，有多个方案并存反而是好事——给开发者更多选择，避免单点依赖风险！💪
