本文介绍了如何从零搭建 MySQL 主从复制环境，包括主数据库设置、数据导出导入、复制配置及验证过程。

---

## 一、主数据库设为只读模式

在执行数据导出前，需要确保主库数据不会被写入。

```bash
flush tables with read lock;
```

---

## 二、修改从数据库 Server ID

为避免主从冲突，修改从数据库的 `server_id`：

```sql
set global server_id=2;
```
> 注意：此数值应与 `my.cnf` 中配置保持一致。

---

## 三、导出主数据库

使用 `mysqldump` 导出主库：

```bash
mysqldump -uroot -p --all-databases > master.sql
```

---

## 四、导入到从数据库

在从库中执行：

```bash
mysql -uroot -p < master.sql
```

---

## 五、查看主库当前日志位置

此信息将在配置复制时使用。

```sql
show master status;
```

输出示例：

| File | Position |
|------|-----------|
| mysql-bin.00006 | 720164815 |

---

## 六、开启主从复制

在从数据库中执行以下语句：

```sql
STOP SLAVE;
CHANGE MASTER TO
    MASTER_HOST='主库IP',
    MASTER_PORT=3306,
    MASTER_USER='repluser',
    MASTER_PASSWORD='replpassword',
    MASTER_LOG_FILE='mysql-bin.00006',
    MASTER_LOG_POS=720164815;
START SLAVE;
```

---

## 七、验证主从复制状态

在从数据库中执行：

```sql
show slave status\G
```

确认以下两个字段均为 **Yes**：

- `Slave_IO_Running`
- `Slave_SQL_Running`

若一致，说明主从同步成功。

---

## 八、解除主库只读状态

同步建立后，可恢复主库的写入权限：

```bash
unlock tables;
```

---

## 九、设置从数据库为只读

为防止数据被误修改：

```bash
set global read_only=1;
```

---

## 十、控制同步的开启与停止

**停止同步：**

```sql
STOP SLAVE;
```

**开启同步：**

```sql
START SLAVE;
```
