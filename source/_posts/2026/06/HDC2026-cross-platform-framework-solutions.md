华为开发者大会 2026（HDC 2026）将于 **6月12日-14日** 在东莞松山湖盛大举行。今年的主题是「脑洞全开，共启新程」，HarmonyOS 全新版本、鸿蒙 AI 核心能力以及生态全新成果将重磅发布。

在众多精彩议程中，**6月13日下午的「跨平台框架解决方案」专题论坛**绝对不容错过。该论坛汇聚了百度、快手、腾讯、美团、京东、同程旅行等中国顶尖应用开发者，从构建和使用的视角，分享跨平台框架和库在 HarmonyOS 生态中的共建成果和应用实践经验。

> 📍 **时间**：6月13日 14:00 - 17:15
> 📍 **地点**：三丫坡 B3-2F-218

## 论坛亮点速览

本场论坛涵盖目前主流的跨平台技术路线——**KMP（Kotlin Multiplatform）**、**React Native**、**Flutter**，以及华为自研的 **CJMP 跨平台框架**，堪称 HarmonyOS 跨端技术的全景式呈现。

从议程分布上看，**KMP 异军突起**，占据了近一半的议题；但 **Flutter 和 React Native 仍是跨平台开发的主流选择**，它们在鸿蒙生态中的适配已进入规模化落地阶段，生态成熟度和开发者基数仍遥遥领先。三者并非替代关系，而是在不同场景下各有所长、协同共存。

KMP 是本场论坛最大的亮点，**7个议题中有6个都与 KMP 直接相关**，可谓异军突起。国内头部互联网应用——百度网盘、快手、抖音、腾讯视频、番茄小说、懂车帝——都将分享其 KMP 在鸿蒙上的实践成果。

> **💡 怎么看 KMP 的崛起？** KMP 之所以在 HarmonyOS 生态中快速起势，核心在于它**共享业务逻辑、灵活选择 UI 框架**的架构理念，与鸿蒙生态初期需要快速适配大量应用的需求高度契合。它让厂商能以较低成本将核心业务逻辑迁移到鸿蒙，而无需全面重写 UI 层。但需要注意的是，KMP 在鸿蒙上仍处于早期规模化阶段，其开发者生态、工具链成熟度和第三方库支持，与 Flutter 和 React Native 相比仍有差距。

特别值得关注的是 **腾讯视频的 Compose 动态化实践**，以及 **番茄小说与懂车帝联手带来的 KMP 跨端实战分享**，这些都是在真实大规模用户场景中的一线经验。

虽然 KMP 的风头正劲，但 **React Native 和 Flutter 作为跨平台开发的主流框架，在鸿蒙生态中依然占据不可替代的位置**。两者拥有更庞大的开发者社区、更成熟的工具链和更丰富的第三方库生态，是绝大多数跨平台项目的首选技术栈。

React Native 方面，**美团**将分享其在鸿蒙上 RN 新架构的演进和实践——这是自研架构在鸿蒙上的重要落地；**华为商城**则会带来社区版本实践和性能优化的干货。

最令人期待的是华为自研的 **CJMP 跨平台框架**首次亮相，**京东**也将带来 TN & CJMP 的高性能跨平台框架优化实践——这是鸿蒙生态下的原生跨平台方案，值得广大开发者重点关注。

## 跨平台框架全景：从"三足鼎立"到"多强并存"

从这份议程可以看出几个重要趋势：

### 1. KMP 异军突起，Flutter / RN 仍是主流底座

Kotlin Multiplatform 在 HarmonyOS 生态中占据了最大篇幅，百度、快手、抖音、腾讯等头部应用都已深度投入。这确实说明 KMP 在鸿蒙适配窗口期抓住了机遇，以"共享逻辑 + 灵活 UI"的模式快速切入。

但需要清醒认识的是：**Flutter 和 React Native 仍然是跨平台开发的主流选择**。全球范围内，Flutter 拥有超过 70 万开发者，React Native 的 npm 周下载量超过 2000 万，两者在生态成熟度、第三方库丰富度、人才储备上仍然遥遥领先。KMP 的崛起更多是在鸿蒙这一特定场景下的"补位"和"增量"，而非替代。

三者正在形成互补格局：**KMP 适合核心业务逻辑共享 + 原生 UI 的场景，Flutter 适合追求跨端一致渲染体验的场景，React Native 适合 Web 技术栈团队快速迁移的场景。** 对于大型应用而言，甚至可能出现多框架共存、各司其职的架构。

### 2. React Native 和 Flutter 从"能不能用"进化为"如何用好"

美团、华为商城（RN）和同程旅行（Flutter）的分享说明，这两大主流框架在 HarmonyOS 上的适配已经进入规模化落地阶段。如果说去年的重点是"跑起来"，今年的关键词则是"性能优化"和"深度集成"。

### 3. CJMP——华为自研跨平台框架浮出水面
CJMP 的首次公开介绍，配合京东的实践分享，预示着华为正在构建自己的跨平台解决方案。这可能是 HarmonyOS 生态从"兼容其他框架"走向"构建自有标准"的关键一步。
