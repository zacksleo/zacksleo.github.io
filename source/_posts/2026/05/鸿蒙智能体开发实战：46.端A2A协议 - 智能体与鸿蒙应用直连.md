## 前言

**A2A（Agent-to-Agent）协议**是鸿蒙智能体平台中用于**智能体之间直接通信**的标准化协议。它允许HarmonyOS设备上的每个应用都可以实现自己的**应用内Agent（App Agent）**，与小艺的**Client Agent**通过标准协议进行对话，实现**跨应用的智能协作**。

本文是 **「鸿蒙智能体开发实战」** 系列的第四十六篇，系统讲解端A2A协议的技术规范、核心组件和开发实现，帮助开发者为自己的HarmonyOS应用接入智能体能力。

> **前置条件**：熟悉HarmonyOS Ability扩展开发。本文档参考鸿蒙端A2A对接规范V0.6。

## 一、A2A协议概述

### 1.1 什么是端A2A

端A2A（End-side Agent-to-Agent）是华为鸿蒙系统中**小艺Client Agent与应用内Agent**之间的通信协议。与传统的端插件不同，A2A协议赋予应用内Agent**主动感知上下文、处理复杂任务、呈现自定义UI**的能力，将智能交互从"工具调用"升级为"智能体协作"。

![端A2A协议架构](https://blog.shaohushuo.com/images/鸿蒙智能体开发实战/kb-46.1.png)

*上图展示了端A2A协议的总体架构：小艺Client Agent通过A2A协议与各App内的Agent建立连接，实现跨应用的智能协作。*

### 1.2 A2A vs 端插件

| 特性 | 端A2A协议 | 端插件 |
|------|-----------|--------|
| **通信模式** | 双向、持续会话 | 单向、一次调用 |
| **上下文管理** | 支持会话级Context | 无上下文 |
| **任务生命周期** | Task管理，支持长时任务 | 单次请求-响应 |
| **UI能力** | 自定义卡片 | 无 |
| **交互复杂度** | 高（多轮对话、状态流转） | 低（工具调用） |
| **实现复杂度** | 较高 | 较低 |

> **选择建议**：如果应用只需要暴露简单功能给智能体调用，使用**端插件**即可；如果应用需要实现**有状态的智能对话**，或需要**主动推送信息和呈现自定义UI**，则选择**端A2A协议**。

## 二、核心概念与层次模型

### 2.1 四层抽象模型

端A2A协议定义了从粗到细的四层抽象模型：

```text
Context（会话）
   └── Task（任务）× N
        └── Artifact（产出物）× N
             └── Part（分片）× N
```

| 层次 | 说明 | 生命周期 |
|------|------|----------|
| **Context** | 会话的逻辑容器，由Agent分配contextId | 持续有效直到失效 |
| **Task** | 任务的完整处理单元，由Agent分配taskId | 从发起到终止 |
| **Artifact** | Task的产出单元，同组内容组合呈现 | 随Task生命周期 |
| **Part** | Artifact的组成分片，如文本、卡片 | 随Artifact生命周期 |

### 2.2 Context - 会话管理

Context是会话的逻辑容器，将一段交互过程中的相关Task归组在一起：

```json
{
  "method": "tasks/send",
  "params": {
    "task": {
      "query": "帮我订一张下周三从北京到上海的机票"
    }
  }
}
```

```json
{
  "method": "tasks/send",
  "result": {
    "contextId": "ctx_abc123",
    "taskId": "task_001",
    "artifactId": "art_001",
    "parts": [
      {
        "type": "text",
        "text": "好的，我来帮您查询下周三北京到上海的航班信息。"
      }
    ]
  }
}
```

**会话失效场景**：
1. **Agent主动失效**：返回错误码`99911222`，小艺收到后不携带contextId重放请求
2. **小艺主动重置**：小艺不携带contextId发起新请求

### 2.3 Task - 任务生命周期

Task状态流转：

```text
CREATED → PROCESSING → COMPLETED
   ↓          ↓
   └── CANCELED ┘
```

| 状态 | 说明 |
|------|------|
| **CREATED** | 任务已创建，等待处理 |
| **PROCESSING** | 任务正在处理中，可发送中间状态更新 |
| **COMPLETED** | 任务处理完成 |
| **CANCELED** | 任务被取消 |

### 2.4 Artifact与Part

```json
  "partId": "part_001",
```

## 三、AgentExtensionAbility

**AgentExtensionAbility**是接入端A2A协议的**必需核心组件**。在DevEco Studio中通过 **New → Extension Ability → Agent** 创建，IDE会自动生成三个文件。

### 3.1 文件结构

```text
entry/src/main/
├── module.json5            # 注册AgentExtensionAbility
├── resources/agent_config/
│   └── agent_config.json   # AgentCard配置
└── ets/AgentExtAbility/
    └── AgentExtensionAbility.ets  # A2A通信实现
```

### 3.2 配置AgentCard

agent_config.json是Agent向小艺声明自身能力的核心配置：

```json
{
  "agentCards": [
    {
      "agentId": "flight-agent",
      "name": "机票助手",
      "description": "提供航班搜索与预订服务，支持多城市、多日期查询",
      "iconUrl": "https://example.com/icon.png",
      "version": "1.2.0",
      "capabilities": {
        "streaming": true,
        "pushNotifications": true,
        "stateTransitionHistory": false
      },
      "defaultInputModes": ["text/plain", "application/json"],
      "defaultOutputModes": ["text/plain", "application/json"],
      "skills": [
        {
          "id": "flight-search",
          "name": "航班搜索",
          "description": "根据出发地、目的地、日期搜索最优航班",
          "tags": ["flight", "search"],
          "examples": [
            "帮我查下周三从北京到上海的上午航班"
          ]
        }
      ]
    }
  ]
}
```

| 字段 | 说明 | 必需 |
|------|------|------|
| **agentId** | 唯一标识Agent的ID | 是 |
| **name** | Agent显示名称 | 是 |
| **description** | Agent功能描述 | 是 |
| **capabilities** | 能力声明（流式、推送等） | 否 |
| **skills** | 技能列表 | 推荐 |

### 3.3 注册配置

```json
{
```

## 四、关键方法与生命周期

### 4.1 方法总览

```typescript
export default class MyAgentExtensionAbility extends AgentExtensionAbility {
  
  // 1. Ability被拉起时触发
  onCreate(want: Want): void { }
  
  // 2. 与小艺建立连接时触发
  onConnect(want: Want, proxy: AgentHostProxy): void { }
  
  // 3. 密钥协商（可选）
  onAuth(proxy: AgentHostProxy, data: string): void { }
  
  // 4. 小艺发送消息时触发
  onData(proxy: AgentHostProxy, data: string): void { }
  
  // 5. 连接断开时触发
  onDisconnect(want: Want, proxy: AgentHostProxy): void { }
  
  // 6. Ability销毁时触发
  onDestroy(): void { }
}
```

### 4.2 onCreate - 初始化

```typescript
onCreate(want: Want): void {
  console.info('Agent Extension Ability created');
  const sessionContext = want.parameters?.['ability.want.params.context'];
  this.initResources();
  this.loadUserPreferences();
}
```

### 4.3 onConnect - 建立连接

```typescript
private agentProxy: AgentHostProxy | null = null;

onConnect(want: Want, proxy: AgentHostProxy): void {
  console.info('Agent connected to Xiaoyi');
  this.agentProxy = proxy;  // 必须保存proxy
  this.sendWelcomeMessage();
}
```

> **重要**：`proxy`对象必须在此处保存，后续的`sendData`、`authorize`等操作都通过它发起。

### 4.4 onAuth - 密钥协商

```typescript
onAuth(proxy: AgentHostProxy, data: string): void {
  const authData = JSON.parse(data);
  const negotiatedResult = this.performKeyAgreement(authData);
  proxy.authorize(JSON.stringify(negotiatedResult));
}

private performKeyAgreement(data: any): object {
  return {
    status: 'success',
    sessionKey: 'generated-session-key'
  };
}
```

### 4.5 onData - 核心消息处理方法

```typescript
onData(proxy: AgentHostProxy, data: string): void {
  const message = JSON.parse(data);
  
  switch (message.method) {
    case 'tasks/send':
      this.handleTaskSend(proxy, message.params);
      break;
    case 'tasks/cancel':
      this.handleTaskCancel(proxy, message.params);
      break;
    case 'context/clear':
      this.handleContextClear(proxy, message.params);
      break;
  }
}

private handleTaskSend(proxy: AgentHostProxy, params: any): void {
  const { taskId, query } = params.task;
  
  // 首帧：确认收到
  proxy.sendData(JSON.stringify({
    method: 'tasks/send',
    result: {
      contextId: this.currentContextId,
      taskId: taskId,
      artifactId: `art_${Date.now()}`,
      parts: [{ type: 'text', text: '正在处理您的请求...' }]
    }
  }));
  
  // 异步处理任务
  this.processTask(query).then(result => {
    // 返回最终结果
    proxy.sendData(JSON.stringify({
      method: 'tasks/send',
      result: {
        contextId: this.currentContextId,
        taskId: taskId,
        artifactId: `art_${Date.now() + 1}`,
        parts: [
          { type: 'text', text: result.summary },
          { type: 'card', content: result.cardData }
        ],
        state: 'completed'
      }
    }));
  });
}
```

### 4.6 onDisconnect与onDestroy

```typescript
onDisconnect(want: Want, proxy: AgentHostProxy): void {
  console.info('Agent disconnected');
  this.currentContextId = null;
  this.activeTasks.clear();
  this.agentProxy = null;
}

onDestroy(): void {
  console.info('Agent Extension Ability destroyed');
  this.releaseResources();
}
```

### 4.7 proxy核心方法

| 方法 | 说明 | 调用时机 |
|------|------|----------|
| **sendData** | 向小艺发送处理结果 | onData中调用 |
| **authorize** | 向小艺回传密钥协商结果 | onAuth中调用 |

```typescript
// 发送Task状态更新
proxy.sendData(JSON.stringify({
  method: 'tasks/statusUpdate',
  params: {
    taskId: 'task_001',
    state: 'processing',
    progress: 0.5,
    message: '正在查询航班数据...'
  }
}));

// 回传认证结果
proxy.authorize(JSON.stringify({
  status: 'approved',
  errorMessage: null
}));
```

## 五、AgentUIExtensionAbility

### 5.1 创建UI Extension

如果Agent需要以**自定义卡片**形式呈现内容，可以实现AgentUIExtensionAbility（可选）：

```json
    {
      "name": "AgentUIExtensionAbility",
      "srcEntry": "./ets/AgentUIExtAbility/AgentUIExtAbility.ets",
      "description": "机票卡片UI",
      "type": "agentUI",
      "exported": true
    }
  ]
}
```

### 5.2 实现UI卡片

```typescript
import { UIExtensionAbility, UIExtensionContentSession } from '@kit.AbilityKit';

export default class AgentUIExtAbility extends UIExtensionAbility {
  
  onSessionCreate(want: Want, session: UIExtensionContentSession): void {
    const payload = want.parameters?.['ability.want.params.payload'] as string;
    const cardData = JSON.parse(payload || '{}');
    
    session.loadContent('pages/FlightCardPage', {
      context: this.context,
      params: {
        flights: cardData.flights || [],
        title: cardData.title || '航班信息'
      }
    });
  }
}
```

## 六、完整通信时序

### 6.1 标准对话流程

```text
小艺Client Agent          App Agent
      │                        │
      │  1. 建立连接           │
      │─────────────────────>  │
      │                        │
      │  2. tasks/send         │
      │─────────────────────>  │
      │                        │
      │  3. 首帧响应           │
      │<─────────────────────  │
      │                        │
      │  4. 中间状态更新       │
      │<─────────────────────  │
      │                        │
      │  5. 最终结果(含卡片)   │
      │<─────────────────────  │
      │                        │
      │  6. 新Task...          │
      │                        │
      │  7. 断开连接           │
```

### 6.2 密钥协商流程

```text
小艺Client Agent          App Agent
      │                        │
      │  1. 密钥协商请求       │
      │─────────────────────>  │
      │                        │
      │  2. onAuth触发         │
      │                        │
      │  3. authorize回传      │
      │<─────────────────────  │
      │                        │
      │  4. 继续A2A通信        │
```

## 七、实战技巧

### 7.1 会话管理

```typescript
private activeContexts: Map<string, ContextState> = new Map();

interface ContextState {
  contextId: string;
  userId: string;
  createdAt: number;
  lastActiveAt: number;
  activeTasks: Set<string>;
}

private createContext(agentId: string): string {
  const contextId = `ctx_${agentId}_${Date.now()}`;
  this.activeContexts.set(contextId, {
    contextId,
    userId: '',
    createdAt: Date.now(),
    lastActiveAt: Date.now(),
    activeTasks: new Set()
  });
  return contextId;
}
```

### 7.2 流式输出优化

```typescript
async function* streamResponse(proxy: AgentHostProxy, taskId: string) {
  const chunks = ['正在', '查询', '北京', '到', '上海', '的', '航班'];
  
  for (const chunk of chunks) {
    proxy.sendData(JSON.stringify({
      method: 'tasks/send',
      result: {
        taskId,
        artifactId: `art_stream_${Date.now()}`,
        parts: [{ type: 'text', text: chunk }]
      }
    }));
    await new Promise(resolve => setTimeout(resolve, 100));
    yield chunk;
  }
}
```

## 八、FAQ与排查指南

### 8.1 常见问题

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| **Agent无法连接** | 配置文件错误 | 检查agent_config.json格式和module.json5配置 |
| **onData收不到消息** | 连接已断开 | 检查onConnect中的proxy保存逻辑 |
| **卡片显示异常** | payload传递失败 | 确认使用ability.want.params.payload传参 |
| **会话失效** | contextId过期 | 检查Agent主动失效逻辑中的错误码99911222 |

### 8.2 开发调试建议

1. **使用日志追踪**：在每个生命周期方法中添加`console.info`日志
2. **验证AgentCard配置**：确保skills的描述准确，帮助小艺正确路由
3. **优先实现基础流程**：先实现标准对话流程，再添加密钥协商等可选功能
4. **真机验证**：端A2A需要真机环境测试，模拟器可能无法完整验证

## 总结

本文详细介绍了鸿蒙端A2A协议的核心概念、组件实现和通信流程。**端A2A协议是鸿蒙智能体生态从"工具调用"迈向"智能体协作"的关键基础设施**。通过实现AgentExtensionAbility，开发者可以让自己的HarmonyOS应用拥有**自主对话、任务管理、自定义UI**等智能体能力，实现与小艺Client Agent的深度协作。

关键要点：

1. A2A协议的**四层抽象模型**（Context/Task/Artifact/Part）提供了灵活的会话管理能力
2. **AgentExtensionAbility**是必需的核心组件，管理全生命周期通信
3. **AgentUIExtensionAbility**提供自定义卡片的呈现能力
4. 合理使用**流式输出**和**状态更新**可以显著提升用户体验
