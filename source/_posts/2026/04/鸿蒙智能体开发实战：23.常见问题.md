# 鸿蒙智能体开发实战：常见问题

## 前言

在鸿蒙智能体开发、测试和上架过程中，开发者可能会遇到各种问题。本文整理了从开发到上架全流程中最常见的 **20+ 个问题** 及其解决方案，涵盖A2A协议、知识库、工作流、插件、调试、部署和上架审核等各个环节。建议收藏本文，遇到问题时快速查阅。

## API与协议类问题

### 流式输出不生效

**问题描述**：智能体调用A2A接口的 `message/stream` 方法时，返回的数据不是SSE流式格式，而是一次性返回。

**原因分析**：A2A协议的流式响应要求返回的数据格式符合SSE规范，并且需要包含正确的error字段结构。

**解决方案**：

确保接口返回的JSON数据中包含 `error.code` 字段，且 `code` 的值为 **0**：

```json
{
  "error": {
    "code": 0,
    "message": "success"
  }
}
```

完整的SSE流式响应格式示例：

```json
data: {"jsonrpc":"2.0","id":"task-001","result":{"taskId":"task-001","kind":"status-update","final":false,"status":{"state":"working","message":{"text":"正在处理..."}}},"error":{"code":0,"message":"success"}}

data: {"jsonrpc":"2.0","id":"task-001","result":{"taskId":"task-001","kind":"artifact-update","final":false,"artifact":{"parts":[{"kind":"text","text":"你好！我是智能助手。"}]}},"error":{"code":0,"message":"success"}}

data: {"jsonrpc":"2.0","id":"task-001","result":{"taskId":"task-001","kind":"artifact-update","final":true,"artifact":{"parts":[{"kind":"text","text":"你好！我是智能助手。"}]}},"error":{"code":0,"message":"success"}}
```

> **关键点**：每一行SSE数据必须以 `data:` 开头，并以两个换行符 `\n\n` 结束。`error.code` 必须为0，否则客户端可能无法正确解析流式数据。

### 鉴权失败

**问题描述**：请求A2A接口时返回401错误。

| 错误码 | 含义 | 常见原因 |
|--------|------|---------|
| 401 | Unauthorized | API Key错误或过期 |
| 403 | Forbidden | 没有权限访问该资源 |
| 429 | Too Many Requests | 请求频率超过限制 |

**排查步骤**：

```bash
# 1. 检查API Key是否正确设置
echo $VOLCANIC_API_KEY

# 2. 检查API Key是否过期或失效
# 登录火山引擎控制台查看API Key状态

# 3. 测试API连通性
curl -X POST https://api.volcengine.com/ark/v1/chat/completions \
  -H "Authorization: Bearer $VOLCANIC_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-r1","messages":[{"role":"user","content":"hello"}]}'
```

### 会话过期

**问题描述**：A2A接口返回"session not found"或"session expired"错误。

**原因分析**：A2A协议中，`initialize` 方法返回的 `agentSessionId` 有一定有效期（默认为7天）。如果会话过期，需要重新初始化。

**解决方案**：

```python
import httpx

BASE_URL = "http://localhost:8080"
session_id = None

def get_or_create_session():
    """获取或创建会话，处理会话过期"""
    global session_id
    
    if session_id is None:
        session_id = initialize_session()
    return session_id

def initialize_session():
    """初始化新会话"""
    response = httpx.post(
        f"{BASE_URL}/agent/message",
        json={
            "jsonrpc": "2.0",
            "id": 1,
            "method": "initialize"
        }
    )
    data = response.json()
    return data["result"]["agentSessionId"]

def send_message(text):
    """发送消息，自动处理会话过期"""
    global session_id
    
    try:
        sid = get_or_create_session()
        response = httpx.post(
            f"{BASE_URL}/agent/message",
            headers={
                "Content-Type": "application/json",
                "agent-session-id": sid
            },
            json={
                "jsonrpc": "2.0",
                "id": 2,
                "method": "message/stream",
                "params": {
                    "id": "task-001",
                    "sessionId": "session-001",
                    "message": {
                        "role": "user",
                        "parts": [{"kind": "text", "text": text}]
                    }
                }
            }
        )
        data = response.json()
        
        # 检测会话过期
        if "error" in data and data["error"]["code"] != 0:
            if "session" in str(data["error"]["message"]).lower():
                # 重置session_id，重新初始化
                session_id = None
                return send_message(text)
        
        return data
    except Exception as e:
        print(f"请求失败: {e}")
        return None
```

### SSE 连接中断

**问题描述**：使用SSE流式接口时，连接意外断开，用户无法收到完整的回复。

**常见原因与解决方案**：

| 原因 | 症状 | 解决方案 |
|------|------|---------|
| Nginx缓冲开启 | 连接卡住，不返回数据 | 关闭proxy_buffering |
| 超时时间过短 | 长回复被截断 | 增加proxy_read_timeout |
| 防火墙拦截 | 连接拒绝 | 检查防火墙规则 |
| 客户端超时 | 客户端主动断开 | 增加客户端timeout |

**Nginx配置修复**：

```nginx
location /agent/message {
    proxy_pass http://127.0.0.1:8080;
    
    # SSE支持：关闭缓冲
    proxy_set_header Connection "";
    proxy_http_version 1.1;
    proxy_set_header X-Accel-Buffering no;
    proxy_buffering off;
    proxy_cache off;
    
    # 超时设置（长回复需要更大的超时）
    proxy_connect_timeout 60s;
    proxy_send_timeout 300s;
    proxy_read_timeout 300s;
}
```

```bash
# 1. 确认插件API定义正确

# 4. 查看调试台日志
```

### 工作流执行异常

**问题描述**：配置的工作流在实际运行中未按预期执行，某些节点跳过了或重复执行。

**常见原因**：

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| 节点未执行 | 条件判断不满足 | 检查选择器节点条件 |
| 循环异常 | 循环条件配置错误 | 设置最大循环次数 |
| 数据丢失 | 节点间数据传递失败 | 检查变量映射配置 |
| 超时失败 | 节点执行超过超时限制 | 增加超时时间 |

**调试方法**：

1. 进入智能体编排页面
2. 在调试与预览区域发送测试消息
3. 点击回复下方的调试图标
4. 在调试台中查看工作流各节点的执行情况

### 知识库检索无结果

**问题描述**：智能体绑定了知识库，但回答问题时没有基于知识库内容回答，或者直接返回"未找到相关信息"。

**排查清单**：

```python
# 知识库问题排查清单
checklist = {
    "知识库已发布": False,  # 确认知识库状态为"已上架"
    "智能体已绑定": False,  # 确认在智能体编排中已添加该知识库
    "阈值设置合理": False,  # 确认检索文本相关阈值不过高
    "知识库内容匹配": False,  # 确认知识库中有与问题相关的内容
    "查询改写开启": False,  # 确认查询改写功能已开启（多轮对话）
}

for item, checked in checklist.items():
    if not checked:
        print(f"请检查: {item}")
```

## 真机测试相关问题

### 真机测试不生效

**问题描述**：发布真机测试后，在手机小艺中看不到"开发中"的智能体。

**排查步骤**：

1. **检查有效期**：真机测试发布后15天有效，过期需要重新发布
2. **检查白名单**：确认测试账号已在用户组白名单中
3. **检查账号权限**：确认测试账号拥有小艺开放平台权限
4. **检查团队归属**：测试账号必须是当前团队账号下的成员
5. **重启小艺**：发布后需要重新启动小艺
6. **等待生效**：发布后需等待3-5分钟

### 用户组创建失败

**问题描述**：添加测试用户时提示"仅可添加本团队账号下的成员"。

**解决方案**：

```bash
# 1. 确认用户是否已成为团队成员
# 进入开发者联盟 → 团队管理 → 创建团队并添加成员

# 2. 确认用户已获得小艺开放平台权限
# 在添加团队成员时，需要勾选"小艺开放平台"权限

# 3. Inhouse账号限制
# Inhouse类型的账号无法为成员添加小艺开放平台权限
# 如需真机测试，请使用主账号
```

## 上架审核类问题

### 智能体名称审核不通过

**问题描述**：提交上架审核后，智能体名称被驳回。

**常见驳回原因**：

| 问题类型 | 示例 | 正确做法 |
|---------|------|---------|
| 宽泛通用词 | "客服"、"律师"、"北京" | "智能客服助手"、"法律咨询顾问" |
| 极限词 | "最好"、"第一"、"最便宜" | 使用描述性语言 |
| 测试词 | "test"、"beta"、测试 | 去掉或替换 |
| 营销词 | "免费"、"促销"、"XX元" | 避免商业化词汇 |
| 命名不规范 | 繁体字、特殊符号 | 使用简体中文或中英文结合 |

**命名建议**：

> 智能体名称应直观表达其功能，例如：**"产品使用指南助手"**、**"旅游行程规划师"**、**"代码审查助手"**。

### 内容合规审核不通过

**问题描述**：智能体内容被判定为违规或不合规。

**常见合规问题**：

- **AI标识缺失**：生成的内容未按要求添加AI生成标识
- **拟人化问题**：智能体被判定为拟人化（参考《人工智能拟人化互动服务管理暂行办法》）
- **内容安全**：包含敏感词、不当言论或违法信息
- **虚假宣传**：包含未经证实的功能声明

**合规检查清单**：

```markdown
## 内容合规自查清单

### AI标识检查
- [ ] 文本输出是否添加了AI标识
- [ ] 图片生成是否添加了显式或隐式标识
- [ ] 是否符合《人工智能生成合成内容标识办法》要求

### 内容安全检查
- [ ] 不包含色情、暴力、赌博等违规内容
- [ ] 不包含虚假或误导性信息
- [ ] 不包含侵犯知识产权的内容
- [ ] 不涉及非法金钱交易或赌博

### 功能合规检查
- [ ] 功能稳定，无闪退、白屏等问题
- [ ] 不包含诱导跳转、恶意导流等行为
- [ ] 权限申请合理，有明确用途说明

### 隐私合规检查
- [ ] 提供了隐私政策链接
- [ ] 收集个人信息需用户同意
- [ ] 不超范围收集个人信息
```

### 大模型备案审核不通过

**问题描述**：智能体上架时大模型备案信息填写错误被驳回。

**常见问题**：

1. **备案信息填写不准确**：模型名称、备案编号等信息填写错误
2. **使用未备案模型**：使用了未通过算法备案的大模型
3. **AI标识填写错误**：未正确标注生成内容的AI身份标识

**备案信息填写原则**：

```plaintext
场景一：使用小艺开放平台提供的三方大模型
→ 大模型备案信息选择"否"（无需额外备案）

场景二：使用非平台提供的三方大模型
→ 大模型备案信息选择"是"
→ 填写生成式人工智能服务上线备案号
→ 填写算法备案号
```

**备案号查询方式**：

- **生成式AI备案号**：登录[国家互联网信息办公室公告](https://www.cac.gov.cn/2025-09/10/c_1759222982377536.htm)查询
- **算法备案号**：登录[互联网信息服务算法备案系统](https://beian.cac.gov.cn/#/index)查询

### 权限用途描述问题

**问题描述**：审核驳回原因是"权限用途描述不准确"。

**正确示例**：

```plaintext
✅ 正确："提供本地生活服务，如推荐附近门店"
✅ 正确："根据当前位置信息查询天气数据"
❌ 错误："获取位置"（过于模糊）
❌ 错误："为了提供更好的服务"（没有说明具体用途）
```

**填写规则**：

- **明确**：直接说明权限用于什么功能
- **准确**：结合智能体实际场景描述
- **具体**：避免模糊的通用描述

## 调试台相关问题

### 调试台无数据

**问题描述**：进入调试台后没有显示任何调试数据。

**可能原因**：

1. 调试台需要先发送消息并收到回复后才有数据
2. 可能选择了错误的会话时间
3. 浏览器缓存问题

**解决方案**：

```bash
# 调试台使用步骤
1. 在编排页面右侧的调试与预览区域发送一条消息
2. 等待智能体回复
3. 点击回复右上角的调试按钮
4. 确认进入调试台后查看当前会话详情
```

### 获取sessionId用于问题定位

**问题描述**：需要向技术支持提供sessionId用于排查问题。

**获取方法**：

1. 打开浏览器开发者工具（F12）
2. 选择"网络"（Network）标签
3. 发送一条消息与智能体对话
4. 找到名为"run"的请求
5. 在请求消息（Payload）中找到 `sessionId` 和 `interactionId`

## 部署环境相关问题

### 端口冲突

**问题描述**：启动服务时提示端口已被占用。

**解决方法**：

```bash
# 查找占用端口的进程
lsof -i :8080

# 终止占用进程
kill -9 <PID>

# 或修改使用的端口
# 启动时指定其他端口
python main.py --port 8081
```

### Docker 容器无法访问外部API

**问题描述**：容器内调用外部API时超时或连接失败。

**常见原因**：

- Docker网络模式配置问题
- 环境变量未传递到容器内
- DNS解析问题

**验证方法**：

```bash
# 进入容器测试网络连通性
docker exec -it agent-container sh
# 在容器内执行
wget -q -O- http://example.com
# 检查环境变量
echo $VOLCANIC_API_KEY
```

## 其他常见问题

### 智能体响应不符合预期

**问题描述**：智能体的回答内容与期望不符，或者回答质量较低。

**排查方向**：

| 问题类型 | 可能原因 | 解决方案 |
|---------|---------|---------|
| 回答错误 | 知识库配置不当或模型选择不匹配 | 检查知识库检索配置，尝试更换模型 |
| 回答过长 | 角色指令中未约束回复长度 | 在角色指令中增加字数限制 |
| 回答过短 | 模型参数设置不当 | 调整max_tokens等参数 |
| 回答风格不符 | 角色指令中未定义风格 | 完善角色指令的风格描述 |

### 知识库更新不生效

**问题描述**：更新了知识库内容，但智能体仍然使用旧的知识回答问题。

**原因**：知识库更新后需要重新发布才能生效，而且使用该知识库的智能体需要重新加载。

**解决方案**：

1. 进入知识库管理页面
2. 更新知识内容
3. 等待数据处理完成
4. 点击"上架"发布更新
5. 在智能体配置中确认知识库版本已更新

### 模型调用费用过高

**问题描述**：智能体上线后，发现大模型API调用费用超出预期。

**优化策略**：

```python
# 费用优化建议
optimization_tips = [
    "1. 选择性价比更高的模型",
    "2. 设置合理的max_tokens避免超长回复",
    "3. 使用知识库减少模型需要处理的信息量",
    "4. 优化角色指令，减少不必要的上下文",
    "5. 启用工作流的条件分支，避免不必要的节点执行"
]
```

## 流式输出不生效

接口返回的json数据中，即使成功，也需要有 "error.code" 字段，且为 code 的 值 0

```json
{
  "error": {
      "code": 0,
      "message": "success"
  }
}
```
