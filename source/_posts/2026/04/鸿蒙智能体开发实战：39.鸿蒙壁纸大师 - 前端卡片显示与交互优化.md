## 引言

在前端展示层面，鸿蒙壁纸大师充分利用了**鸿蒙 A2A 协议的卡片能力**，通过 `DisplayFaCard` 实现丰富的交互式 UI，而非简单的文本对话。整个壁纸创作流程中，用户看到的是**可点击的选择列表**、**生动的进度提示**和**精美的壁纸展示卡片**。

本文将深入解析前端的卡片交互设计，涵盖 `selectList` 选择卡片、`wallpaper` 展示卡片、SSE 事件驱动的前端更新以及内容安全策略。

## 一、卡片体系总览

### 1.1 三种卡片类型

鸿蒙壁纸大师使用了三种卡片类型：

| 卡片类型 | 用途 | 展示阶段 |
|---------|------|---------|
| **selectList** | 交互式选择列表 | 风格选择、主题选择、场景选择 |
| **wallpaper** | 壁纸结果展示 | 壁纸生成完成 |
| **text** | 文本消息 | 闲聊、进度提示 |

> **核心概念**：`DisplayFaCard` 是鸿蒙 A2A 协议中卡片展示的统一入口，通过 `cardName` 字段区分不同卡片类型，前端根据 `cardName` 渲染对应的 UI 组件。

### 1.2 卡片 JSON 结构规范

所有卡片都通过 A2A 协议的 `artifact-update` 事件的 `parts` 字段传递：

```json
{
  "jsonrpc": "2.0",
  "id": "request_id",
  "result": {
    "taskId": "task_id",
    "kind": "artifact-update",
    "append": false,
    "lastChunk": true,
    "final": true,
    "artifact": {
      "artifactId": "task_id-options",
      "parts": [
        {
          "kind": "data",
          "data": {
            "cardsInfo": [
              {
                "cardName": "selectList",
                "cardData": { ... },
                "displayType": "DisplayFaCard"
              }
            ]
          }
        }
      ]
    }
  },
  "error": { "code": 0, "message": "success" }
}
```

## 二、selectList 选择卡片

### 2.1 卡片构建函数

```python
# agent_routes.py


def build_style_options_card(
    title: str,
    options: List[str],
    task_id: str,
    request_id: str,
    has_next_batch: bool = True,
    can_replay: bool = True,
) -> dict:
    """构建风格/主题选项的卡片 SSE 事件"""
    items = [{"text": opt, "value": opt} for opt in options]
    return {
        "jsonrpc": "2.0",
        "id": request_id,
        "result": {
            "taskId": task_id,
            "kind": "artifact-update",
            "append": False,
            "lastChunk": True,
            "final": True,
            "artifact": {
                "artifactId": f"{task_id}-options",
                "parts": [{
                    "kind": "data",
                    "data": {
                        "cardsInfo": [{
                            "cardName": "selectList",
                            "cardData": {
                                "title": title,
                                "items": items,
                                "canReplay": can_replay,
                            },
                            "displayType": "DisplayFaCard"
                        }]
                    }
                }]
            }
        },
        "error": {"code": 0, "message": "success"}
    }
```


```python
# agent_routes.py - 换一批处理

if "换一批" in user_text:
```

```python
# wallpaper_flow_service.py

def handle_generate_complete(self, image_urls: List[str]) -> Dict[str, Any]:
    """处理生成完成"""
    self.current_step = FlowStep.RESULT

    # 记录生成的壁纸
    for url in image_urls:
        self.generated_wallpapers.append({
            "url": url,
            "style": self.selected_style,
            "theme": self.selected_theme,
        })

    # 扣除免费次数
    if self.free_credits_remaining > 0:
        self.free_credits_remaining -= 1

    return {
        "step": "result",
        "message": "你的专属艺术壁纸已生成完成！",
        "wallpapers": [
            {"url": url, "style": self.selected_style, "theme": self.selected_theme}
            for url in image_urls
        ],
        "credits_remaining": self.free_credits_remaining,
        "has_regenerate": self.free_credits_remaining > 0,
    }
```

## 四、SSE 事件驱动的前端更新

### 4.1 完整事件序列

从前端视角看，一次完整的壁纸生成过程如下：

```
前端发送 message/stream 请求
    ↓（后端返回 SSE 流）
事件1: status-update   →  state: submitted    →  "正在理解您的需求..."
事件2: status-update   →  state: working      →  "正在优化描述..."
事件3: status-update   →  state: working      →  "正在生成图片..."
事件4: status-update   →  state: working      →  "正在构思画面构图..."
事件5: status-update   →  state: working      →  "正在勾勒轮廓..."
...
事件N: artifact-update →  final: true         →  wallpaper 卡片
```

### 4.2 前端处理逻辑（示意）

```typescript
// 前端 SSE 事件处理示意代码

const eventSource = new EventSource('/agent/message');

eventSource.onmessage = (event) => {
    const data = JSON.parse(event.data);
    const result = data.result;

    switch (result.kind) {
        case 'status-update':
            // 更新进度状态
            updateProgress(result.status.message.parts[0].text);
            break;

        case 'artifact-update':
            // 处理最终产物
            const cardsInfo = result.artifact.parts[0].data.cardsInfo;
            cardsInfo.forEach(card => {
                switch (card.cardName) {
                    case 'selectList':
                        renderSelectListCard(card.cardData);
                        break;
                    case 'wallpaper':
                        renderWallpaperCard(card.cardData);
                        break;
                }
            });
            break;
    }
};
```

### 4.3 卡片替换逻辑

每次推送新的 `selectList` 卡片时，前端需要替换上一张卡片：

- **`append: false`**：替换上一张卡片（风格→主题→场景的步骤推进）
- **`append: true`**：追加到已有内容（闲聊的逐 token 输出）

```
风格选择卡片 (append: false)
    ↓ 用户选择风格
主题选择卡片 (append: false) → 替换风格卡片
    ↓ 用户选择主题
场景选择卡片 (append: false) → 替换主题卡片
    ↓ 用户选择场景
进度文本 (append: false)
    ↓ 逐条追加
进度文本 (append: true)
    ...
    ↓
壁纸卡片 (append: false) → 替换所有内容
```

## 五、内容安全策略

### 5.1 肖像检测

```python
# wallpaper_flow_service.py

def check_content_policy(user_text: str) -> Tuple[bool, Optional[str]]:
    """检查内容是否符合规范（肖像、文字等限制）"""
    # 肖像检测关键词
    portrait_keywords = [
        "我", "自己", "本人", "照片", "肖像", "人脸", "头像",
        "明星", "网红", "模特", "人物", "人像", "自拍",
    ]

    # 文字/水印检测关键词
    text_keywords = [
        "文字", "字体", "写字", "名字", "姓名", "签名",
        "水印", "logo", "LOGO", "标志", "品牌",
    ]

    # 检测肖像请求
    for keyword in portrait_keywords:
        if keyword in user_text:
            if any(phrase in user_text for phrase in ["像我", "我的照片", "加入", "添加", "包含"]):
                return False, "抱歉呀，为了版权和隐私安全，我暂时不能生成包含人物肖像的壁纸哦～"

    # 检测文字/水印请求
    for keyword in text_keywords:
        if keyword in user_text:
            if any(phrase in user_text for phrase in ["添加", "写上", "显示", "包含", "要有"]):
                return False, "抱歉，目前暂时无法在壁纸上添加文字、水印或 LOGO～"

    return True, None
```

### 5.2 无关话题检测

```python
# wallpaper_flow_service.py

def is_irrelevant_topic(user_text: str) -> bool:
    """判断是否是无关话题（闲聊、知识问答等）"""
    # 壁纸相关关键词
    wallpaper_keywords = [
        "壁纸", "背景", "桌面", "风格", "主题", "画面", "图片",
        "生成", "创作", "设计", "图案", "色彩", "色调",
        "锁屏", "主屏", "横屏", "竖屏", "尺寸", "分辨率",
    ]

    # 检查是否包含壁纸相关关键词
    for keyword in wallpaper_keywords:
        if keyword in user_text:
            return False

    # 常见的无关问题类型
    irrelevant_patterns = [
        "你是谁", "你能做什么", "天气", "新闻", "股票",
        "帮我", "写代码", "翻译", "计算",
    ]
    for pattern in irrelevant_patterns:
        if pattern in user_text:
            return True

    return False


def get_irrelevant_response() -> str:
    """获取无关问题的统一回应"""
    return "我是你的专属壁纸创作助手，只专注于为你生成精美鸿蒙壁纸哦～我们继续设计你的专属壁纸吧！"
```

### 5.3 安全策略在流程中的位置

```python
# agent_routes.py - generate_sse() 中的安全检查

# 1. 内容政策检查（肖像、文字等）
policy_passed, policy_reject_reason = check_content_policy(user_text)
if not policy_passed:
    # 返回拒绝卡片
    reject_event = { ... "text": policy_reject_reason }
    yield f"data: {json.dumps(reject_event)}\n\n"
    return

# 2. 无关话题检查（闲聊、知识问答等）
if is_irrelevant_topic(user_text):
    # 引导回壁纸主题
    irrelevant_event = { ... "text": get_irrelevant_response() }
    yield f"data: {json.dumps(irrelevant_event)}\n\n"
    return

# 3. 通过检查后，继续处理正常流程
```

### 5.4 内容安全的交互设计

安全策略被触发时，用户看到的是**友好的引导信息**而非冷冰冰的错误提示：

| 违规类型 | 用户输入示例 | 系统回复 |
|---------|-------------|---------|
| 肖像请求 | "加入我的照片" | "为了版权和隐私安全，不能生成包含人物肖像的壁纸哦～" |
| 文字请求 | "写上'我爱你'" | "暂时无法在壁纸上添加文字、水印或 LOGO～" |
| 无关话题 | "帮我写代码" | "只专注于为你生成精美鸿蒙壁纸哦～" |

> **安全设计原则**：内容安全策略应始终返回友好的引导信息而非冷冰冰的错误码，让用户感受到智能体的温度。同时，所有安全检查必须在进入主流程之前完成，避免浪费 API 调用资源。

## 七、常见问题与解决方案

在前端卡片开发中，常见问题及解决方案如下：

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 卡片不显示 | `cardName` 或 `displayType` 字段错误 | 检查 JSON 结构，确保使用 `DisplayFaCard` |
| 卡片重叠 | `append` 设置为 `true` | 多级选择流程中使用 `false` |
| 选项点击无响应 | 前端未正确处理点击事件 | 确保将选项文本作为用户消息发送 |
| SSE 连接断开 | 网络超时或服务端异常 | 前端实现自动重连机制 |
| 图片加载失败 | `imageUrl` 无效或过期 | 检查图片 URL 的有效期 |

## 八、最佳实践总结

在鸿蒙壁纸大师的前端卡片交互开发中，以下最佳实践值得参考：

| 最佳实践 | 说明 | 收益 |
|---------|------|------|
| 三级选择流程 | 风格→主题→场景的渐进式引导 | 降低用户决策成本 |
| 卡片替换机制 | 使用 `append: false` 替换上一张卡片 | 保持界面简洁 |
