## 前言

当智能体执行**耗时较长的任务**时（如AI绘图、视频生成、批量数据处理），用户可能暂时离开智能体。当任务执行成功后，如何及时通知用户？**消息推送**功能正是为解决这一场景而设计的。

鸿蒙智能体平台提供了**Webhook消息推送**机制，允许智能体在后台任务完成后，通过推送通知的方式告知用户。本文将详细介绍消息推送的配置方法和API规范。

> 消息推送是提升用户体验的关键功能——不需要用户一直等待，任务完成后自动通知，实现"即走即用"的流畅体验。

## 一、消息推送概述

### 1.1 什么是消息推送

消息推送是指智能体在**后台任务执行完成**后，主动向用户发送通知消息的机制。这与即时通信中的消息推送类似，但更加智能化。

推送场景示例：

1. **AI绘图**：用户请求生成一张图片，智能体处理完成后推送结果
2. **视频生成**：长视频渲染完成后通知用户查看
3. **数据分析**：大量数据处理完成后推送分析报告
4. **定时任务**：定时执行的批量任务完成后通知

### 1.2 推送类型

鸿蒙消息推送支持两种类型的通知消息：

| 推送类型 | 说明 | 效果 |
|---------|------|------|
| **text** | 纯文本通知 | 点击后进入智能体，展示文本内容 |
| **data** | 结构化数据通知 | 点击后触发触发器的任务执行，展示执行结果 |

> 注意：如果同时发送 text 和 data 类型消息，只有 text 消息生效。

### 1.3 推送流程

完整的消息推送流程如下：

```
步骤1: 用户发起耗时任务（如"帮我画一幅山水画"）
步骤2: 智能体开始处理，用户可离开
步骤3: 任务完成后，智能体服务器调用Webhook API
步骤4: 华为推送服务将通知发送到用户设备
步骤5: 用户收到推送通知
步骤6: 用户点击通知，进入智能体查看结果
```

## 二、配置推送功能

### 2.1 添加推送变量

首先需要在智能体的**变量配置**中添加 `push_id` 变量：

1. 进入智能体编排页面
2. 找到「变量」配置区域
3. 添加系统变量 `push_id`
4. 保存配置

![配置push_id变量](/images/鸿蒙智能体开发实战/image-9.1.png)

`push_id` 变量说明：

| 属性 | 说明 |
|------|------|
| 变量名 | `push_id` |
| 类型 | 系统变量（只读） |
| 用途 | 代表通过Webhook推送通知时使用的唯一ID |
| 获取方式 | 请求中的系统变量，自动生成 |

### 2.2 Webhook凭证配置

消息推送使用**Webhook事件**的凭证进行鉴权：

1. 进入小艺开放平台 → 「工作空间」→「凭证」
2. 点击「新建凭证」
3. 设置Key名称并保存
4. 保存生成的Key（Access Key）和安全密钥（Security Key）

> 注意：安全密钥只在创建成功时可复制，关闭窗口前请务必妥善保管。该凭证通用，可供该账号下所有智能体的Webhook使用。

### 3.2 请求头格式

请求头字段说明：

| 字段 | 类型 | 说明 | 是否必填 |
|------|------|------|---------|
| `x-hag-trace-id` | string | 随机生成的请求标识，用于问题定位 | 是 |
| `X-Access-Key` | string | 凭证的Access Key | 是 |
| `X-Sign` | string | HMAC-SHA256签名 | 是 |
| `X-Ts` | string | 当前时间戳（毫秒） | 是 |

### 3.3 签名计算

签名算法使用 **HMAC-SHA256**，具体实现如下：

```python
import hashlib
import hmac
import base64
import time

def generate_sign(secret_key: str, timestamp: str = None) -> str:
    """生成X-Sign签名
    
    Args:
        secret_key: 从小艺开放平台获取的安全密钥
        timestamp: 时间戳（毫秒），为空则自动生成
        
    Returns:
        base64编码的签名结果
    """
    if timestamp is None:
        timestamp = str(int(time.time() * 1000))
    
    # 使用HMAC-SHA256算法
    message = timestamp.encode('utf-8')
    secret = secret_key.encode('utf-8')
    
    sign = hmac.new(
        secret,
        message,
        hashlib.sha256
    ).digest()
    
    # Base64编码
    return base64.b64encode(sign).decode('utf-8')


def verify_sign(secret_key: str, timestamp: str, sign: str, timeout: int = 900) -> bool:
    """验证签名
    
    Args:
        secret_key: 安全密钥
        timestamp: 请求中的时间戳
        sign: 请求中的签名
        timeout: 签名超时时间（秒），默认15分钟
        
    Returns:
        签名是否有效
    """
    # 验证时间戳是否在有效期内（防重放攻击）
    now = int(time.time() * 1000)
    if abs(now - int(timestamp)) > timeout * 1000:
        return False
    
    # 重新计算签名并比对
    expected_sign = generate_sign(secret_key, timestamp)
    return sign == expected_sign
```

Java示例：

```java
import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;
import java.nio.charset.StandardCharsets;
import java.util.Base64;

public class SignUtil {
    public static String generateSign(String secret, String ts) throws Exception {
        Mac mac = Mac.getInstance("HmacSHA256");
        SecretKeySpec keySpec = new SecretKeySpec(
            secret.getBytes(StandardCharsets.UTF_8), "HmacSHA256"
        );
        mac.init(keySpec);
        byte[] byteHMAC = mac.doFinal(ts.getBytes(StandardCharsets.UTF_8));
        return Base64.getEncoder().encodeToString(byteHMAC);
    }
}
```

签名验证示例：

```python
# 验证参数
secret = "2e3b71f5def64d95a727314f028bf5aa"
ts = "1547630863716"

# 计算签名
sign = generate_sign(secret, ts)
print(f"签名结果: {sign}")
# 预期输出: 6lFqepUu79KSxVCsrXyB/aLVFIdutsTLLx1cZjxDE4I=
```

> 提示：服务端应校验ts与当前时间差值的绝对值不超过15分钟，用于防重放攻击。

## 五、 Data数据类型推送

### 5.1 触发插件任务

使用data类型推送可以触发智能体执行插件任务：

```json

    "kind": "data",
    "data": {
        "cityName": "南京"
    }
}
```

触发后，插件使用data中的参数执行任务。

### 5.2 触发工作流任务

data类型推送也可以触发工作流执行：

```json
{
    "kind": "data",
    "data": {
        "cityName": "南京"
    }
}
```

触发后，参数作为 `EVENT_INPUT.payload` 传递给工作流：

```json
{
    "payload": {
        "cityName": "南京"
    },
    "header": {
        "name": "CloudEvent",
        "namespace": "Common"
    }
}
```

## 六、最佳实践

### 6.1 推送策略建议

1. **合理设置pushText**：简明扼要说明任务结果，如"图片已生成完成！"
2. **避免频繁推送**：短时间内多次推送可能被系统聚合
3. **区分重要级别**：重要任务推送，次要任务在下次打开时展示
4. **附带上文信息**：让用户看到通知就知道是哪个任务的结果

### 6.2 错误处理

```python
# 推送错误处理和重试逻辑
import time
import requests

def send_push_notification(push_data: dict, max_retries: int = 3):
    """发送推送通知，支持重试"""
    
    url = "https://hag.cloud.huawei.com/open-ability-agent/v1/agent-webhook"
    headers = {
        "Content-Type": "application/json",
        "x-hag-trace-id": generate_trace_id(),
        "X-Access-Key": ACCESS_KEY,
        "X-Sign": generate_sign(SECRET_KEY),
        "X-Ts": str(int(time.time() * 1000))
    }
    
    for attempt in range(max_retries):
        try:
            response = requests.post(url, json=push_data, headers=headers, timeout=10)
            if response.status_code == 200:
                return response.json()
            elif response.status_code == 429:
                # 限流，等待后重试
                time.sleep(2 ** attempt)
                continue
            else:
                # 其他错误，记录日志
                log_error(f"Push failed: {response.status_code} - {response.text}")
                return None
        except requests.RequestException as e:
            log_error(f"Push request error: {e}")
            time.sleep(2 ** attempt)
    
    return None
```

### 6.3 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 推送未收到 | push_id未配置 | 检查变量中是否添加了push_id |
| 签名验证失败 | secret_key错误 | 检查凭证配置是否正确 |
| 推送内容为空 | pushText为null | 确保设置了pushText字段 |
| 接口超时 | 网络问题 | 检查网络连接，增加超时时间 |
| HTTP 401 | 鉴权失败 | 检查Access Key是否正确 |
| HTTP 429 | 请求过于频繁 | 增加重试间隔 |
