# 鸿蒙智能体开发实战：使用触发器

## 前言

在智能体的日常运行中，除了被动响应用户的对话请求外，很多时候还需要**自动触发**特定的任务执行。例如，当用户进入智能体时自动展示欢迎信息，或者当外部系统完成某个异步任务时向用户推送通知。**触发器（Trigger）** 就是实现这种自动化能力的关键机制。本文将详细介绍鸿蒙智能体平台中触发器的两种类型——通用事件和Webhook事件，帮助你掌握智能体的自动化任务编排能力。

## 触发器概述

### 什么是触发器

触发器是智能体的一种**事件驱动**机制，它允许智能体在接收到特定事件时**自动**执行预设的任务，而无需等待用户主动输入。这类似于编程领域的观察者模式或被观察者模式——当事件发生时，系统会自动回调已注册的处理逻辑。

> **核心价值**：触发器让智能体从"被动问答"进化到"主动服务"，极大地扩展了智能体的应用场景。

### 触发器类型对比

鸿蒙智能体平台目前支持两种类型的触发器：

| 特性 | 通用事件 | Webhook事件 |
|------|---------|------------|
| **触发方式** | 用户进入智能体时自动触发 | 外部系统通过HTTP请求触发 |
| **适用模式** | LLM模式、A2A模式 | 所有模式 |
| **任务类型** | 智能体提示、插件、工作流 | 插件、工作流、A2A协议 |
| **是否需要凭证** | 否 | 是（Access Key & Security Key） |
| **典型场景** | 进入欢迎语、自动数据查询 | 异步任务完成通知、外部系统回调 |

## 通用事件

### 通用事件原理

通用事件是最简单的触发器形式，当用户以**半屏态**或**全屏态**进入智能体时，系统会自动触发执行预先配置的任务。一个智能体内一个通用事件仅可关联一个触发器。

![通用事件触发器配置](https://blog.shaohushuo.com/images/鸿蒙智能体开发实战/kb-14.1.png)

> 上图展示了在小艺开放平台中配置通用事件触发器的界面，开发者可以在【任务执行】中选择智能体提示、插件或工作流。

### 任务执行类型

通用事件支持三种任务执行类型：

#### 1. 智能体提示

触发时系统将预设的内容发送给智能体执行，适合用于欢迎语、引导提示等场景：

```json
{
  "trigger": {
    "type": "common_event",
    "task": {
      "type": "agent_prompt",
      "content": "欢迎来到智能体！我是你的专属助手，请问有什么可以帮助你的？"
    }
  }
}
```

#### 2. 插件

触发器任务执行类型为插件时，触发时系统将自动调用插件执行：

```python
# 触发器调用插件的配置示例
trigger_config = {
    "event": "common_event",
    "task": {
        "type": "plugin",
        "plugin_id": "weather_query_plugin",
        "parameters": {
            "city": "${system.city}"
        },
        "save_context": True  # 是否保存会话上下文
    }
}
```

> **提示**：插件支持通过参数设置进行融合生成配置，也支持使用模拟集进行调试。详情可参考相关资源中的链接。

#### 3. 工作流

触发器任务执行类型为工作流时，触发时系统将自动调用工作流执行：

```python
# 触发器调用工作流的配置示例
trigger_config = {
    "event": "common_event",
    "task": {
        "type": "workflow",
        "workflow_id": "daily_report_workflow",
        "parameters": {
            "user_id": "${system.uid}"
        },
        "save_context": True
    }
}
```

> **注意**：由触发器触发工作流时，因为没有用户主动输入，工作流无法自动关联默认输入的 `USER_INPUT`。因此，触发器绑定的工作流需要在开始节点定制其他输入参数，并在触发器中指定参数值。

### 通用事件配置步骤

配置通用事件触发器只需以下几步：

1. 进入智能体编排页面，找到**触发器**配置区域
2. 选择**通用事件**作为事件选项
3. 配置任务执行类型（智能体提示/插件/工作流）
4. 填写任务参数
5. 保存并发布智能体

## Webhook事件

### Webhook事件概述

Webhook事件适用于**异步事件场景**。当内容生成完成或任务执行完成时，开发者需要向华为开放的统一接口发送通知消息。发送成功后用户手机端将收到通知消息，用户点击通知消息后进入智能体，可以查看任务执行结果。

> **应用场景**：图片生成完成通知、数据报告生成完成通知、异步任务处理结果推送等。

### 通知消息类型

Webhook通知消息分为两种类型：

| 类型 | 说明 |
|------|------|
| **text** | 点击通知消息进入智能体后，将text内容展示给用户 |
| **data** | data作为入参触发触发器的任务执行，并将执行结果答复给用户 |

> **注意**：若同时发送text和data类型消息，只有text消息生效。

### Webhook事件触发器配置

#### 配置字段说明

| 配置项 | 说明 |
|--------|------|
| **Access Key** | 从小艺开放平台获取的触发器事件WebHook分配的Key |
| **Security Key** | 用于生成签名的安全密钥 |
| **任务执行类型** | 支持插件、工作流、A2A模式 |
| **保存会话上下文** | 是否将任务执行信息保存至上下文 |

#### 凭证创建

在配置Webhook事件前，需要先创建凭证：

1. 进入**小艺开放平台**
2. 选择【工作空间】-【凭证】
3. 点击**新建凭证**
4. 设置Key名称后保存
5. 保存后将生成Key和安全密钥

> **重要提醒**：安全密钥只在创建成功时可明文复制，关闭窗口前请务必复制并妥善保管。创建的凭证通用，可供本账号下所有智能体的Webhook事件使用。

### Webhook API详解

#### 接口端点

```bash
POST https://hag.cloud.huawei.com/open-ability-agent/v1/agent-webhook
Content-Type: application/json
Accept: application/json
```

#### 请求头

| Header | 说明 |
|--------|------|
| `x-hag-trace-id` | 请求标识，使用随机数生成，用于问题定位 |
| `X-Access-Key` | 从小艺开放平台获取的Access Key |
| `X-Sign` | 签名，`Base64(HMAC-SHA256(secretKey, ts))` |
| `X-Ts` | 当前时间戳（毫秒） |

#### 签名生成示例

```python
import hmac
import hashlib
import base64
import time

def generate_sign(secret_key: str, timestamp: str = None) -> str:
    """
    生成Webhook请求签名

    Args:
        secret_key: 安全密钥
        timestamp: 时间戳（毫秒），为空则自动生成

    Returns:
        Base64编码的签名
    """
    if timestamp is None:
        timestamp = str(int(time.time() * 1000))

    message = timestamp.encode('utf-8')
    secret = secret_key.encode('utf-8')
    sign = hmac.new(secret, message, hashlib.sha256).digest()
    return base64.b64encode(sign).decode('utf-8')

# 使用示例
secret_key = "your-security-key-here"
ts = str(int(time.time() * 1000))
sign = generate_sign(secret_key, ts)
print(f"Timestamp: {ts}")
print(f"Signature: {sign}")
```

### Java签名示例

```java
import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;
import java.util.Base64;

public class WebhookSigner {

    public static String generateSign(String secretKey, String timestamp) throws Exception {
        Mac mac = Mac.getInstance("HmacSHA256");
        SecretKeySpec secretKeySpec = new SecretKeySpec(
            secretKey.getBytes("UTF-8"), "HmacSHA256"
        );
        mac.init(secretKeySpec);
        byte[] rawHmac = mac.doFinal(timestamp.getBytes("UTF-8"));
        return Base64.getEncoder().encodeToString(rawHmac);
    }

    public static void main(String[] args) throws Exception {
        String secretKey = "your-security-key";
        String timestamp = String.valueOf(System.currentTimeMillis());
        String sign = generateSign(secretKey, timestamp);

        System.out.println("Timestamp: " + timestamp);
        System.out.println("Signature: " + sign);
    }
}
```

## 触发器在不同模式下的差异

不同的智能体编排模式下，触发器的行为和能力有所差异：

| 特性 | LLM模式 | A2A模式 | 工作流模式 |
|------|---------|---------|-----------|
| **通用事件** | ✅ 支持 | ✅ 支持 | ❌ 不支持 |
| **Webhook事件** | ✅ 支持 | ✅ 支持 | ✅ 支持 |
| **智能体提示任务** | ✅ | ✅ | ❌ |
| **插件任务** | ✅ | ✅ | ✅ |
| **工作流任务** | ✅ | ✅ | ✅（配合选择器节点）|

> **工作流模式的特殊说明**：工作流编排时，可以配合选择器节点使用。当工作流开始节点的 `EVENT_INPUT.EventPayload` 包含特殊参数键值时走触发器触发任务流，否则走对话逻辑流。

### 1. 选择合适的触发器类型

```python

# 场景三：定时触发工作流

        "parameters": {
            "userId": "${system.uid}"
        }
    }

```

### 2. 插件和工作流的版本管理

触发器绑定的插件或工作流升级时，**暂不支持触发器自动更新**，需手动重新绑定插件或工作流。因此建议：

- 在升级前记录触发器绑定的插件/工作流版本
- 升级后在触发器中重新选择最新版本
- 在测试环境中先验证再更新生产环境

### 3. 错误处理与重试

```python
# Webhook发送失败时的重试逻辑
import time
import requests

def send_webhook_with_retry(url, headers, payload, max_retries=3):
    """发送Webhook通知并支持重试"""
    for attempt in range(max_retries):
        try:
            response = requests.post(url, headers=headers, json=payload)
            if response.status_code == 200:
                print(f"Webhook发送成功，attempt={attempt + 1}")
                return True
            else:
                print(f"Webhook返回异常状态码: {response.status_code}")
        except requests.exceptions.RequestException as e:
            print(f"Webhook发送失败，attempt={attempt + 1}, error={e}")

        if attempt < max_retries - 1:
            time.sleep(2 ** attempt)  # 指数退避

    return False
```

## 常见问题（FAQ）

### Q1：智能体中同时配置了工作流和触发器，如何实现对话逻辑和触发器功能并存？

**答**：工作流编排时，可以配合**选择器节点**使用。当工作流开始节点的 `EVENT_INPUT.EventPayload` 包含特殊参数键值时走触发器触发任务流，否则走对话逻辑流。

### Q2：Webhook发送后用户没有收到通知消息？

**答**：请检查以下几点：
1. 确认Access Key和Security Key是否正确配置
2. 确认签名生成算法是否正确
3. 检查通知消息的pushId是否正确
4. 确认用户设备的小艺APP版本在11.3.8.300及以上

### Q3：一个触发器可以绑定多个任务吗？

**答**：一个Webhook触发器可以绑定一个任务（插件/工作流/A2A）。如果需要执行多个任务，可以通过工作流节点编排多个任务顺序执行。

## 七、触发器配置检查清单

在发布智能体前，建议逐项确认触发器相关配置：

1. **通用事件**：确认任务类型和参数是否正确
2. **Webhook 事件**：确认 Access Key 和 Security Key 是否妥善保存
3. **签名算法**：确认服务端签名逻辑与平台要求一致
4. **测试覆盖**：在真机和网页端分别验证触发效果

> **建议**：将触发器配置纳入版本管理文档，避免升级插件或工作流后遗漏重新绑定。
