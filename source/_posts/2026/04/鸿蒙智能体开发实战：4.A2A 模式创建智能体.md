## 前言

在前面的文章中，我们介绍了**单Agent模式**的智能体创建与编排。然而在实际业务场景中，智能体往往需要与**外部服务**进行交互——查询天气、预订酒店、处理支付等。本期文章将详细介绍**A2A（Agent-to-Agent）模式**，这是鸿蒙智能体平台对外提供能力的关键模式。

A2A模式允许开发者搭建**自己的API服务**，让小艺智能体通过标准协议调用你的服务端能力。相较于单Agent模式的"开箱即用"，A2A模式更**灵活**、**可扩展**，适合需要集成**三方服务**或**自有业务逻辑**的场景。

> A2A是Google在2025年提出的开放智能体通信协议标准，鸿蒙智能体平台在兼容该标准的基础上，针对鸿蒙生态进行了深度适配和扩展。

## 一、A2A协议概述

### 1.1 协议起源与发展

**A2A（Agent-to-Agent）** 是Google在2025年提出的开放智能体通信协议，旨在解决不同厂商构建的智能体之间无法互通的**"孤岛"问题**。它提供了一套标准的通信语言，让智能体之间可以安全地交换信息、协调任务。

核心设计理念：

1. **基于JSON-RPC 2.0**：请求和响应采用标准化的JSON格式，易于理解和实现
2. **单一端点**：所有方法通过 `/agent/message` 统一路由，结构清晰
3. **会话管理**：内置Session机制，支持多轮对话
4. **鉴权机制**：支持基于密钥的身份验证，保证接口安全
5. **流式输出**：通过SSE协议支持实时结果推送

### 1.2 鸿蒙A2A与Google A2A对比

鸿蒙A2A在兼容Google A2A协议的基础上，增加了鸿蒙生态特有的能力：

| 对比维度 | Google A2A | 鸿蒙A2A |
|---------|-----------|---------|
| 基础协议 | JSON-RPC 2.0 + SSE | JSON-RPC 2.0 + SSE |
| 端点设计 | 单一Endpoint | 单一Endpoint，`/agent/message` |
| 会话模式 | 基于session | 两种模式：session模式/无session模式 |
| 认证方案 | Bearer Token | AK/SK、API Key、OAuth多种 |
| 流式类型 | message/stream | message/stream + 增强artifact-update |
| 端侧能力 | 不支持 | 端侧插件、端侧指令、设备上下文 |
| 授权机制 | 标准OAuth | 华为账号一键授权登录 |
| 特殊消息 | 标准类型 | 增加reasoningText、data等多种Part类型 |

> 鸿蒙A2A在兼容Google标准的基础上，重点强化了**端云协同**和**账号授权**能力，这是鸿蒙生态的核心优势。

## 二、A2A智能体架构

### 2.1 三大核心角色

A2A模式下，智能体的工作涉及三个核心角色：

![A2A架构图](/images/鸿蒙智能体开发实战/4-1.png)

**上图展示了A2A模式下智能体的整体架构和调用逻辑。**

**小艺开放平台**：负责智能体的元数据注册和认证配置。开发者在平台上创建智能体时，需要配置API URL、认证信息等元数据，平台将这些信息注册到智能体执行引擎。

**智能体执行引擎**：平台的运行时核心，负责智能体的**规划澄清**、**路由分发**和**编排调度**。当用户发起对话时，执行引擎通过A2A协议调用开发者搭建的API服务，并将返回的结果通知给智能体。

**应用智能体服务器**：开发者自行搭建的API服务，接收智能体执行引擎发来的A2A请求，处理业务逻辑并返回响应。

### 2.2 整体调用流程

完整的调用流程如下：

1. **用户发起对话**：用户在设备上与小艺对话，触发智能体
2. **意图识别**：智能体执行引擎接管请求，进行意图理解和规划
3. **协议调用**：引擎通过A2A协议调用开发者的API服务
4. **业务处理**：开发者服务处理请求，返回响应
5. **结果展示**：执行引擎处理结果通知，呈现给用户

主要特点：

1. 服务器侧不需要维护长连接，支持断线重连
2. 基于StreamableHTTP + JSON RPC协议
3. 支持SSE流式输出，首Token即可推送

### 2.3 会话维持机制

鸿蒙A2A提供**两种会话模式**：

**模式一：基于session维护状态（推荐方案）**

由服务器侧分配 `agent-session-id`，类似于MCP的 `mcp-session-id`。客户端每次请求服务器侧时，将 `agent-session-id` 放在header中带给服务器侧。

- 服务器需要实现 `initialize` 和 `notifications/initialized` 方法
- 需要对同一AK/SK同时分配多个 `agent-session-id`（建议不低于5个）
- 可防止多个客户端请求时的凭证吊销间隙问题

**模式二：无session简化版**

客户端每次请求时都在header中携带认证凭据（AK/SK、APIKey等）。

- 不需要实现 `initialize`、`notifications/initialized` 方法
- 适用于轻量级场景

## 四、A2A基础配置

基础配置是A2A模式的关键步骤，**必须完成此节点配置，否则无法正常发布智能体**。

![A2A基础配置入口](/images/鸿蒙智能体开发实战/4-4.png)

### 4.1 API URL

配置服务端API地址，格式如下：

```
https://your-domain.com/agent/message
```

注意事项：

- 必须是**公网可访问**的HTTPS地址
- 统一使用 `/agent/message` 作为端点
- 支持自定义域名或IP地址（推荐使用域名）

### 4.2 会话维持方式

| 维持方式 | 说明 | 适用场景 |
|---------|------|---------|
| 服务器侧分配Session | 服务器通过initialize方法分配agentSessionId | 推荐方案，功能完整 |
| 不维持Session | 每次请求携带认证凭据 | 轻量级场景，简化开发 |

### 4.3 认证信息

平台支持多种认证方式：

| 认证方式 | 说明 | 安全等级 |
|---------|------|---------|
| Access Key / Secret Key | 对称密钥认证 | 高 |
| API Key | 单一密钥认证 | 中 |
| OAuth 2.0 | 标准授权协议 | 高 |
| 无认证 | 不进行接口认证 | 低（不推荐） |

设置Access Key和Secret Key后，鸿蒙智能体调用时会携带认证信息用于服务端验证：

```json
// 请求Header示例
POST /agent/message
Content-Type: application/json
Authorization: Bearer <access_key>
agent-session-id: <session_id>
```

### 4.4 方法声明

在配置中声明支持的A2A方法，让执行引擎知道你的服务器支持哪些操作：

| 方法 | 说明 | 是否必须 |
|------|------|---------|
| `initialize` | 初始化会话 | 推荐 |
| `notifications/initialized` | 通知初始化完成 | 推荐 |
| `message/stream` | 流式消息处理 | 是 |
| `tasks/cancel` | 取消任务 | 否 |
| `clearContext` | 清理对话上下文 | 否 |

### 4.5 账号登录授权

如果你的服务需要识别用户身份，需要配置**华为账号登录授权**：

1. 在华为开发者联盟[申请appId](https://developer.huawei.com/consumer/cn/doc/HMSCore-Guides/web-preparations-0000001050050891)
2. 在小艺开放平台注册appId
3. 配置用户授权回调地址

用户在智能体内点击账号授权后，流程如下：

1. 已授权用户：静默发起授权，服务器返回新的 `agentLoginSessionId`
2. 未授权用户：弹框获取授权，服务器基于华为账号授权码获取用户手机号
3. 后续请求携带 `agentLoginSessionId` 字段进行身份识别

> 提示：`agentLoginSessionId` 超期失效后，小艺APP会自动重新发起授权流程，从服务器获取新的ID。

## 五、A2A协议方法详解

### 5.1 Initialize - 初始化会话

`initialize` 是A2A协议的**第一个调用方法**，用于建立服务器之间的通信连接。

```json
// 请求
POST /agent/message
Content-Type: application/json

{
    "jsonrpc": "2.0",
    "id": "msg-001",
    "method": "initialize"
}
```

```json
// 响应
{
    "jsonrpc": "2.0",
    "id": "msg-001",
    "result": {
        "version": "1.0",
        "agentSessionId": "8f01f3d172cd4396a0e535ae8aec6687",
        "agentSessionTtl": 604800
    },
    "error": {
        "code": 0,
        "message": "success"
    }
}
```

关键字段说明：

- `agentSessionId`：服务器返回的唯一会话标识符，后续请求在header中携带
- `agentSessionTtl`：会话有效期（秒），一般建议设置为**7天（604800秒）**

### 5.2 Notifications/Initialized - 通知初始化完成

初始化完成后，客户端通知服务器准备就绪：

```json
POST /agent/message
Content-Type: application/json
agent-session-id: 8f01f3d172cd4396a0e535ae8aec6687

{
    "jsonrpc": "2.0",
    "id": "msg-002",
    "method": "notifications/initialized"
}
```

> 提示：此方法HTTP返回200状态码即可，无需响应体。

### 5.3 Message/Stream - 流式消息处理

核心的消息处理方法，兼容Google A2A的 `message/stream`：

```json
POST /agent/message
Content-Type: application/json
agent-session-id: 8f01f3d172cd4396a0e535ae8aec6687

{
    "jsonrpc": "2.0",
    "id": "msg-003",
    "method": "message/stream",
    "params": {
        "id": "task-001",
        "sessionId": "session-001",
        "message": {
            "role": "user",
            "parts": [{
                "kind": "text",
                "text": "你好，请帮我查询今天的天气"
            }]
        }
    }
}
```

服务器通过SSE协议返回流式响应，包含：

1. `submitted` 状态：表示请求已接收
2. `working` 状态：正在处理中
3. `artifact-update`：输出处理结果
4. `completed` 状态：任务完成

### 5.4 Tasks/Cancel - 取消任务

取消正在执行的任务：

```json
POST /agent/message
Content-Type: application/json
agent-session-id: 8f01f3d172cd4396a0e535ae8aec6687

{
    "jsonrpc": "2.0",
    "id": "msg-004",
    "method": "tasks/cancel",
    "params": {
        "id": "task-001"
    }
}
```

### 5.5 ClearContext - 清理上下文

清理当前对话的上下文信息：

```json
POST /agent/message
Content-Type: application/json
agent-session-id: 8f01f3d172cd4396a0e535ae8aec6687

{
    "jsonrpc": "2.0",
    "id": "msg-005",
    "method": "clearContext",
    "params": {
        "sessionId": "session-001"
    }
}
```

| 方法 | 用途 | 是否需要Session |
|------|------|----------------|
| `initialize` | 初始化通信连接 | 否 |
| `notifications/initialized` | 通知初始化完成 | 是 |
| `message/stream` | 发送消息并获取流式响应 | 是 |
| `tasks/cancel` | 取消正在执行的任務 | 是 |
| `clearContext` | 清理对话上下文 | 是 |

## 六、协议整体交互流程

完整的A2A协议交互时序如下：

```
阶段一：初始化
客户端                             服务器
  |-- initialize ------------------>|
  |<-- agentSessionId + TTL --------|
  |-- notifications/initialized --->|
  |<-- 200 OK ----------------------|

阶段二：消息处理（可多次）
  |-- message/stream --------------->|
  |<-- SSE: status-update(submitted)-|
  |<-- SSE: status-update(working) --|
  |<-- SSE: artifact-update(text) ---|
  |<-- SSE: status-update(completed)-|

阶段三：任务控制（可选）
  |-- tasks/cancel ----------------->|
  |<-- status: canceled -------------|
  |-- clearContext ------------------>|
  |<-- status: cleared --------------|
```

> 提示：每个阶段可以在一个会话生命周期内多次执行，`message/stream` 支持并发多个任务。

## 什么是 A2A

A2A（Agent-to-Agent）是 Google 在 2025 年提出的一种开放智能体通信协议，旨在解决不同厂商构建的智能体之间无法互通的"孤岛"问题。它提供了一套标准的通信语言，让智能体之间可以安全地交换信息、协调任务。

A2A 协议的核心设计理念：

- **基于 JSON-RPC 2.0**：请求和响应采用标准化的 JSON 格式，易于理解和实现
- **单一端点**：所有方法通过 `/agent/message` 统一路由，结构清晰
- **会话管理**：内置 Session 机制，支持多轮对话
- **鉴权机制**：支持基于密钥的身份验证，保证接口安全
- **流式输出**：通过 SSE 协议支持实时结果推送

小艺开放平台兼容了 A2A 协议规范，使得开发者可以为鸿蒙设备构建智能体应用。
